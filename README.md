# Bump

**Pickup volleyball for people who don't have a group yet.**

An interactive mobile app prototype that helps beginners find local volleyball
games at a level where they won't feel out of place. Open `index.html` and use it.

## The barrier

Volleyball is one of the hardest sports to walk into alone. It needs six people
per side, a net, a reserved gym, and a group that already exists. Most people who
want to play never do, because they don't know where games happen or whether
they'd be welcome at one.

Existing apps solve discovery. They work well once you already play. If you
don't, "Intermediate 6v6, Thursday, 8pm" tells you nothing you can act on. The
unsolved part is the on-ramp, and that is what this prototype is about.

## What Bump does differently

| Problem | How the interface answers it |
| --- | --- |
| "Am I intermediate?" is unanswerable for a beginner | Level is set by describing what you can actually do, not by picking a number |
| Listings hide whether you'd be the worst player there | Every game card shows how many attendees marked themselves new |
| Walking into an unfamiliar gym alone is the real fear | Each game shows a minute-by-minute schedule of what happens when you arrive |
| Getting picked last | Hosts assign teams, and the interface says so up front |
| Hosts have no reason to be welcoming | "Welcome first-timers" is a toggle with a stated commitment attached |

## Screens

1. **Find your level** — three plain-language questions resolve into a level.
2. **Games near you** — filtered feed where every card carries beginner signals.
3. **Before you commit** — host note, arrival timeline, what to bring, who's going.
4. **Host a game** — anyone with a court can add supply; welcoming beginners is the default.

## What actually works

The prototype is clickable, not just a picture:

- Choosing an answer on screen 1 rewrites the level summary **and** the filter
  chip on the feed, so the connection between the two screens is visible.
- The feed navigates into the game detail; the tab bar reaches the host form.
- Saving a spot changes the button and reveals the confirmation.
- Chips, segmented controls, and toggles all hold state.

The four-screen gallery below the prototype is generated by cloning each live
screen, so the screenshots and the working app can never drift apart.

## Running it

No build step, no dependencies.

```
git clone https://github.com/<your-username>/bump.git
cd bump
open index.html
```

## Design notes

The palette comes from an indoor court at night: painted floor blue, taped
boundary white, and the yellow panel of a Mikasa ball. Yellow is the only accent
and is spent solely on things the user should notice. Barlow Condensed handles
headings and numbers, which reads as scoreboard and jersey; Inter carries
anything a person has to read carefully.

Interaction detail follows a small set of rules taken from published UI-polish
guidance: concentric border radii (outer radius equals inner radius plus
padding), `scale(0.96)` press feedback, transitions capped at 150ms and limited
to compositor-friendly properties, borders reserved for structure with shadows
carrying elevation, tabular numbers on every figure, 44px minimum hit areas,
visible focus rings, and a full `prefers-reduced-motion` fallback.

The rotation diagram on screen one is a functional part of the question rather
than decoration.
